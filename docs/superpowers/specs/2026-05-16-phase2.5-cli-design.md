# Phase 2.5 Monitoring CLI — Design

**Date:** 2026-05-16
**Status:** Approved
**Branch:** `feat/phase2.5-cli`

---

## Goal

Provide a first-class command-line interface for observing the Nexus Lite system: pipeline status, source/document inventory, span inspection, semantic search, and ingestion triggering. The CLI is the daily operator interface — it replaces poking the REST API with `curl` and querying Postgres with `psql`.

---

## Decisions

| Decision | Choice | Rationale |
|---|---|---|
| Access model | Hybrid: direct DB for reads, HTTP for actions/search | Reads work offline and surface internals; actions hit the canonical API |
| CLI framework | `typer` + `rich` | Auto-generated `--help`, type-hinted args, colored tables |
| Packaging | `[project.scripts]` console entry: `nexus = "app.cli.main:app"` | Daily-use command should be a first-class binary on PATH |
| Output | Rich tables by default; `--json` for raw piping | Human and machine consumers from one command set |

---

## Architecture & Components

### New module: `app/cli/`

```
app/cli/
├── __init__.py
├── main.py     — typer App; defines all sub-commands and dispatches them
├── config.py   — CLISettings (extends pydantic-settings); reads .env
├── db.py       — async read helpers: short-lived asyncpg connection per command
├── http.py     — async HTTP client wrappers around the FastAPI endpoints
└── render.py   — pure formatters: rich.Table builders + JSON serialisers
```

### Layering

- **`main.py`** parses arguments, resolves config, dispatches to either `db.py` (reads) or `http.py` (actions/search). Calls `render.py` with the result.
- **`db.py`** uses the existing `app.db.models` ORM. Each function opens a fresh `AsyncSession` via a one-shot engine, runs the query, returns plain dicts, and disposes the engine. No pool, no lifespan — CLI commands are short-lived.
- **`http.py`** uses `httpx.AsyncClient` with a 10s default timeout. Raises `typer.Exit(1)` on non-2xx with a formatted error message.
- **`render.py`** has one function per output shape: `format_status_table`, `format_sources_table`, `format_documents_table`, `format_document_detail`, `format_search_results`. Each accepts a `json_output: bool` flag; when true, prints JSON and returns; when false, prints a rich.Table.

### Registration

In `pyproject.toml`:
```toml
[project.scripts]
nexus = "app.cli.main:app"
```

After `pip install -e ".[dev]"`, the `nexus` command is on PATH globally for the active Python environment.

### Dependency additions

```toml
"typer>=0.12.0",
"rich>=13.7.0",
```

Both are small, well-maintained, and add no new runtime cost to the server (CLI-only imports).

## Commands

### `nexus status`

Direct DB. Shows pipeline health in one table.

| Field | Source |
|---|---|
| Docs by status | `SELECT status, COUNT(*) FROM documents GROUP BY status` |
| Total spans | `SELECT COUNT(*) FROM spans` |
| Sources (total / enabled) | `SELECT COUNT(*), COUNT(*) FILTER (WHERE enabled) FROM sources` |
| Last ingest | `SELECT MAX(fetched_at) FROM documents` |

Color rules: `fetched` and `chunked` rows shown in yellow if they have any docs older than 1 hour (indicates stuck pipeline). `embedded` always green. Sources shown as `8 (7 enabled)`.

### `nexus sources [--enabled | --disabled]`

Direct DB. Table columns: `id` (short, 8 chars), `name`, `type`, `url` (truncated), `domain_pack`, `enabled`, `credibility`. Defaults to all sources ordered by `created_at desc`.

### `nexus documents [--status X] [--source <id>] [--since <ISO date>] [--limit N]`

Direct DB. Table columns: `id` (short), `title` (40 chars), `source_name`, `status` (colored), `fetched_at`. Default limit: 50. Status colors: `fetched` yellow, `chunked` yellow, `embedded` green, anything else red.

### `nexus document <id>`

Direct DB. Two tables:
1. **Metadata** — id, title, url, source_name, status, content_hash (16 chars), published_at, fetched_at
2. **Spans** — index, token_count, text preview (first 80 chars). Embedding column shown as `[vec(384)]` placeholder, never the raw floats.

### `nexus search "<query>" [--top-k 10] [--domain-pack X]`

HTTP. POSTs to `/search/spans`. Table columns: rank, score (3 decimals, color-graded), source_name, document title, span text preview (100 chars).

### `nexus ingest url <url> [--source-name X] [--domain-pack X]`

HTTP. POSTs to `/ingest/url`. Renders the resulting `IngestResult` (ingested/skipped counts + document IDs).

### `nexus ingest text --title <t> --file <path> [--source-name X] [--domain-pack X]`

HTTP. Reads `<path>` from disk, POSTs to `/ingest/text`. Stdin support deferred.

### `nexus ingest rss <source_id>`

HTTP. POSTs to `/ingest/rss/{source_id}`. Renders the result table.

### Universal flags (all commands)

- `--json` — output raw JSON instead of a table (read commands only)
- `--api-url <url>` — override the default `http://localhost:8000`
- `--db-url <url>` — override `DATABASE_URL` from the env

## Configuration

`app/cli/config.py`:

```python
class CLISettings(BaseSettings):
    api_base_url: str = "http://localhost:8000"
    database_url: str

    model_config = SettingsConfigDict(env_file=".env", extra="ignore")
```

Reads the same `.env` as the server. No new env vars introduced. Flags override per-command.

## Testing

### `tests/test_cli_render.py` — unit, no DB, no HTTP

- `format_status_table` returns the expected text when all stages are populated
- `format_documents_table([])` produces an empty-state row without erroring
- `--json` mode output is `json.loads`-parseable for each renderer
- Stuck-pipeline color rule fires correctly when a `fetched` doc is >1h old

### `tests/test_cli_db.py` — integration, testcontainers

Reuses existing `session_factory` fixture from `tests/conftest.py`.

- `count_by_status` returns correct counts after seeding docs in three states
- `list_sources` filters by `enabled` correctly
- `get_document_with_spans` returns spans sorted by `span_index` and excludes embedding vectors
- `get_status_snapshot` returns last-ingest timestamp matching the most recent doc

### `tests/test_cli_e2e.py` — end-to-end via `typer.testing.CliRunner`

- `nexus status --json` returns parseable JSON with all expected keys
- `nexus documents --status embedded` filters correctly against a seeded DB
- `nexus sources --enabled` returns only enabled sources

### Not in scope for CLI tests

HTTP ingest and search endpoint behavior is already covered by Phase 1/2 tests. The CLI's `http.py` is a thin wrapper; a single smoke test confirming a POST is dispatched correctly is enough — full endpoint coverage stays in `tests/test_search.py` and `tests/test_ingestion.py`.

## Acceptance Criteria

Phase 2.5 is complete when:

1. `pip install -e .` installs the `nexus` console script on PATH
2. All 8 commands work against a running stack (`docker compose up` + at least one ingested document)
3. `nexus status` correctly reports pipeline counts and last-ingest timestamp
4. `--json` flag produces machine-readable output on every read command
5. All new tests pass
6. Existing test suite still passes (no regressions)
